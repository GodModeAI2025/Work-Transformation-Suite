Fünf Claude-Skills · Python 3.9+ · keine Abhängigkeiten

Aus Stellenbeschreibungen wird ein bewerteter Arbeitsgraph.

Rollen, Aufgaben und Skills eines Bereichs, jede Aufgabe auf KI-Automatisierbarkeit bewertet, jede Rolle als eliminiert, transformiert, augmentiert, entstehend oder stabil klassifiziert, dazu eine Agentenbibliothek mit Rollenabdeckung und ein Dashboard. Angefangen hat das mit Pilotbereichen von 20 bis 40 Rollen. Inzwischen läuft es mit über 200 Rollen in einem Durchgang.

Claude urteilt, Skripte rechnen

Die Trennung ist die eigentliche Idee der Suite. Claude liest Quellen und schreibt drei JSON-Dateien: Extraktion, Bewertung, Agentenbündelung. Alles andere machen Python-Skripte, ohne Zufall und ohne Zeitstempel: IDs, Zusammenführung, Normalisierung, Klassifikation, Abdeckung, Dashboard.

01

Gleiche Eingabe, gleiche Ausgabe

IDs sind SHA1-Hashes normalisierter Namen, Listen sortiert, JSON-Schlüssel sortiert. Zwei unabhängige Läufe derselben Eingabe erzeugen byteidentische Dateien.

02

Regeln statt Bauchgefühl

Modus, HAS-Level, Horizont, Disruptionstyp, Abdeckung und Priorität sind Formeln mit Konstanten am Kopf von score_roles.py. Wer kalibrieren will, verschiebt dort die Konstanten und nicht einzelne Bewertungen.

03

Menschen korrigieren an einer Stelle

Fachexperten schreiben Zeilen in overrides.csv. Die gewinnen dauerhaft und überleben jeden Neulauf. Im Graphen selbst wird nie von Hand editiert.

Vier Schritte, ein Datenformat

Alle Schritte arbeiten auf derselben work-graph.json in einem Projektordner. Jeder Schritt, der etwas ändert, legt eine neue Version an. Ein Schritt ohne Änderung meldet „Unverändert“.

Claude + Skript

work-graph-builder

Liest Stellenbeschreibungen aus 00_input/, extrahiert Rollen, Aufgaben, Zeitanteile und Skills, erzeugt den Graphen und die Review-Liste für Fachexperten.

Claude + Skript

task-scorer

Bewertet jede Aufgabe nach sechs Werten der Rubrik und leitet ab: Modus, HAS-Level, Zeithorizont, Disruptionsscore und -typ je Rolle, bleibende und sinkende Skills.

Claude + Skript

agent-mapper

Bündelt Aufgaben zu 6–15 wiederverwendbaren Agenten und rechnet Abdeckung je Rolle, FTE-Äquivalent, Build/Buy/Hybrid, Horizont und Priorität.

Nur Skript

transformation-dashboard

Baut ein einzelnes, offline lauffähiges HTML-Dashboard, drei CSV-Dateien und einen Bericht. Farben kommen aus einer Theme-Datei.

00_input/ Quellen (Mensch) │ Claude extrahiert → 10_extraction/extract_*.json ▼ build_graph.py → 20_graph/work-graph_v001_builder.json │ make_review_list.py → 30_review/review_v001.md ← Fachexperten → overrides.csv ▼ apply_overrides.py → v002_review │ Claude bewertet → 20_graph/scores.json ▼ score_roles.py → v003_scorer │ Claude bündelt → 20_graph/agents.json ▼ compute_coverage.py → v004_mapper ▼ build_dashboard.py → 40_output/dashboard.html, CSV, report.md

python3 skills/work-transformation/scripts/run_pipeline.py --project projekte/kundenservice führt alle Skript-Schritte hintereinander aus. Fehlt eine Claude-Eingabe, stoppt der Lauf mit Exit-Code 3 und einer klaren Meldung. Derselbe Befehl ist das „weiter machen“ nach jeder Korrektur.

Sagt, wie belastbar das Ergebnis ist

Vier Ergänzungen aus dem ersten echten Einsatz, damit aus einer Analyse kein Scheinergebnis wird.

Belastbarkeit je Rolle

Jede Rolle trägt eine Stufe: belastbar, teilweise geprüft, ungeprüft. Sie folgt aus der Quelle der Zeitanteile, der Expertenprüfung, dem Anteil abgeleiteter Aufgaben und dem bekannten Headcount. Eine Rollenkarte, in der alles „ungeprüft“ ist, ist ein Gesprächsangebot, kein Ergebnis.

Kipp-Analyse

Maschinenanteil, Urteilsbedarf und Fehlergewicht werden je Aufgabe um ±1 variiert. Das Ergebnis sagt, ob eine Einstufung stabil, grenznah oder wackelig ist, und nennt die Aufgabe, an der sie hängt. Genau die prüft der Experte zuerst.

Stellen statt Prozessrollen

positions.csv ordnet Stellen mit Anteilen den Rollen zu und rechnet Vollzeitäquivalente und Headcounts. Ohne Personennamen.

Kalibrierung

calibrate.py vergleicht Expertenkorrekturen mit den generierten Werten. Wenn die Experten systematisch anders liegen, verschiebt man den Anker in der Rubrik statt weiter einzeln zu korrigieren.

Installation

Voraussetzung: Python 3.9 oder neuer, keine zusätzlichen Pakete.

In Claude (Cowork / claude.ai)

Die fünf .skill-Dateien aus dist/ einzeln in den Chat ziehen und auf „Skill speichern“ klicken. Reihenfolge egal.

In Claude Code

Als Plugin: /plugin marketplace add GodModeAI2025/Work-Transformation-Suite, dann /plugin install work-transformation-suite@work-transformation-suite. Oder Ordner skills/ nach ~/.claude/skills/ kopieren oder projektbezogen nach <repo>/.claude/skills/. Zusammen in einen Ordner legen, damit die Skills sich über den Geschwister-Pfad finden.

Ohne Claude

Alles läuft auch als reines Kommandozeilenwerkzeug. Die Urteilsschritte macht dann ein Mensch, indem er die drei JSON-Vorlagen ausfüllt.

git clone https://github.com/GodModeAI2025/Work-Transformation-Suite.git
cd Work-Transformation-Suite
python3 skills/work-transformation/scripts/check_suite.py        # → Suite OK

python3 skills/work-graph-builder/scripts/init_project.py \
  --project projekte/kundenservice \
  --name "Kundenservice Pilot" --organization "Meine Firma" \
  --scope "Kundenservice – Vertrag und Abrechnung"

Der Ablauf ist am Pilotbereich mit 20 bis 40 Rollen entstanden und bereits mit über 200 Rollen in einem Dashboard gelaufen. Projektdaten liegen außerhalb des Repositories. Dort stehen nur die Skills.

Grenzen

Was die Suite nicht kann, steht hier, damit niemand es im Piloten herausfinden muss.

  • Kein Freigabeworkflow mit Rollen und Rechten.
  • Keine Integration in SuccessFactors oder andere HR-Systeme.
  • Kein Tracking der Agentennutzung nach dem Rollout.
  • Ein umbenannter Task bekommt eine neue ID und verliert Bewertung und Overrides. Namen also stabil halten.

Für genau die ersten drei Punkte verkaufen kommerzielle Plattformen ihr Produkt. Für die Frage, ob eine solche Analyse für einen Bereich überhaupt belastbare Ergebnisse liefert, reicht die Suite. Bis über 200 Rollen ist sie bisher gelaufen.
